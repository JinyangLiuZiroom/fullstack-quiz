语言与计算层语言与计算层 (Java Core & JVM) 7 个知识点

Java 基础语法：变量、基本类型、引用类型、运算符、条件分支、循环结构。 详情 ›
八种基本类型（byte/short/int/long/float/double/char/boolean）存值，其余全是引用类型存地址。考题常让你判断 `==` 比较的是值还是引用、自动装箱的缓存区间（Integer -128~127）。
Integer a = 100, b = 100;  // a==b -> true (缓存)
Integer c = 200, d = 200;  // c==d -> false (新对象)
System.out.println(c.equals(d)); // true
易考形式考 `==` vs equals、自动装箱缓存区间、基本类型取值范围。
面向对象基础：类、对象、属性、方法、构造方法、封装、继承、多态、接口。 详情 ›
多态靠父类/接口引用指向子类对象，运行时走实际类型的方法。接口只定义契约、无实现（Java 8+ 可有 default 方法）。
interface Animal { void speak(); }
class Dog implements Animal { public void speak(){ System.out.println("woof"); } }
Animal a = new Dog(); a.speak(); // 多态：调 Dog
易考形式考向上转型、重写(Override)规则、接口与抽象类区别。
异常处理：try-catch-finally、throw/throws、常见运行时异常识别。 详情 ›
finally 一定执行（除非 System.exit）；catch 顺序必须是子类在前、父类在后，否则编译不过。RuntimeException 不需 throws。
try { int x = 1/0; }
catch (ArithmeticException e){ }   // 子类在前
catch (Exception e){ }            // 父类在后
finally { System.out.println("always"); }
易考形式考 catch 顺序、finally 执行时机、checked vs unchecked 异常。
强类型系统理解：类型声明、类型转换、泛型基础、编译期类型检查。 详情 ›
泛型只在编译期生效（类型擦除），运行时 `List<String>` 与 `List<Integer>` 是同一份 Class。强制转换失败抛 ClassCastException。
List<String> list = new ArrayList<>();
// 编译期禁止放 Integer；运行期擦除为 List
易考形式考泛型擦除、强制转换异常、菱形操作符 `<>`。
集合框架基础：List、Set、Map 的定义、遍历、增删改查与典型使用场景。 详情 ›
List 有序可重复（ArrayList 数组 / LinkedList 链表）；Set 去重（HashSet 哈希 / TreeSet 排序）；Map 键值对（HashMap 哈希 / TreeMap 排序）。遍历 Map 用 entrySet 最高效。
Map<String,Integer> m = new HashMap<>();
m.put("a",1);
for (var e : m.entrySet()) {   // 优于 keySet 再 get
  System.out.println(e.getKey()+e.getValue());
}
易考形式考 ArrayList vs LinkedList 选择、HashMap 结构、遍历方式性能。
常见集合错误排查：空指针、下标越界、ConcurrentModification、类型转换异常。 详情 ›
遍历时用集合自身方法增删会抛 ConcurrentModificationException；改用迭代器 it.remove() 或 CopyOnWriteArrayList / 并发容器。
for (String s : list) { if (s.isEmpty()) list.remove(s); } // 抛异常
Iterator<String> it = list.iterator();
while(it.hasNext()){ if(it.next().isEmpty()) it.remove(); }
易考形式考 ConcurrentModification 触发条件、安全删除方式。
AI 辅助编码技能：能提供明确需求、错误日志、代码片段，让 AI 修改基础 Java 业务代码并解释原因。 详情 ›
给 AI 要带“上下文”：相关类、报错栈、期望行为，并让它解释改了什么、为什么。盲信生成代码会引入隐蔽 bug。
易考形式考“如何向 AI 描述问题才能得到可用修改”——结构化 Prompt。

应用框架层 8 个知识点

Spring Boot 项目结构识别：controller、service、mapper/dao、entity、config、resources 等目录职责。 详情 ›
Controller 接请求、Service 写业务、Mapper 管 DB、Entity 是表映射、config 放配置类、resources 放配置与静态资源。分层是 Spring 工程的第一原则。
易考形式考目录职责判断、哪层该放什么逻辑。
配置文件读写：application.yml/properties 中端口、数据源、日志、环境配置的含义与修改。 详情 ›
yml 用缩进表达层级，properties 用点号。server.port 改端口，spring.datasource 配数据源，多环境用 application-dev.yml 等 profile。
server:
  port: 8080
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/db
    username: root
易考形式考 yml 缩进、profile 激活、配置项含义。
Spring MVC 接口模板：@RestController、@RequestMapping、@GetMapping、@PostMapping、@PutMapping、@DeleteMapping。 详情 ›
@RestController = @Controller + @ResponseBody，直接返回 JSON。@RequestMapping 可放类上统一定前缀，具体方法用 Get/Post 等语义化注解。
@RestController
@RequestMapping("/users")
public class UserController {
  @GetMapping("/{id}") public User get(@PathVariable Long id){...}
  @PostMapping public User add(@RequestBody User u){...}
}
易考形式考注解含义、REST 语义映射、路径参数。
入参接收：@RequestParam、@PathVariable、@RequestBody、DTO/VO 基础使用。 详情 ›
@RequestParam 收 ?k=v；@PathVariable 收路径 /{id}；@RequestBody 收 JSON 体并反序列化成对象。DTO 是专门承载入参的传输对象。
@GetMapping("/search")
public List<User> search(@RequestParam String name, @RequestParam(defaultValue="1") int page){...}
易考形式考三者区别、何时用 DTO。
参数校验：@Valid、@NotNull、@NotBlank、@Size 等基础注解。 详情 ›
在 @RequestBody 对象字段上加注解，配合 @Valid 触发校验，失败抛 MethodArgumentNotValidException，返回 400。
class CreateUserReq {
  @NotBlank @Size(max=20) String name;
  @NotNull Integer age;
}
@PostMapping public void add(@Valid @RequestBody CreateUserReq req){...}
易考形式考校验注解、@Valid 触发时机、校验失败表现。
统一返回：Result/Response 包装类、状态码、错误信息字段。 详情 ›
前后端约定统一结构：{code, message, data}。成功 code=0/data 有值，失败 code≠0/message 描述。前端按 code 判断而非只看 HTTP 200。
{
  "code": 0,
  "message": "success",
  "data": { "id": 1, "name": "Tom" }
}
易考形式考统一返回结构、业务码 vs HTTP 码。
API 调试：使用 Postman、curl 或 Swagger/Knife4j 调用接口并查看请求、响应、错误码。 详情 ›
Knife4j 是 Spring 的接口文档 UI，可直接试调。curl 看原始响应与状态码；重点盯 Status Code、响应体、错误码。
curl -X POST http://localhost:8080/users \
  -H 'Content-Type: application/json' \
  -d '{"name":"Tom"}'
易考形式考调试工具用途、如何看响应与错误码。
AI 辅助框架学习：能让 AI 解释项目启动流程、配置含义、接口调用链路。 详情 ›
把启动日志、配置片段、Controller→Service→Mapper 调用代码贴给 AI，让它画出调用链路、指出配置含义。
易考形式考“如何用 AI 理解陌生 Spring 项目”。

Controller 不写业务、Mapper 不写业务判断——这是分层红线。业务都进 Service，保证可测试与可复用。
// 反例：Controller 里直接写 SQL/业务
// 正例：Controller 调 service.xxx()，service 调 mapper
易考形式考分层职责判断、反模式识别（Controller 直调 Mapper）。
DTO、VO、Entity 的基础区别与转换场景。 详情 ›
Entity 对应数据库表；DTO 是接口入参/出参传输对象；VO 是给前端展示用的视图对象。跨层传递用 DTO/VO，避免把 Entity 直接暴露。

UserVO vo = new UserVO(u.getId(), u.getName());

拿一个需求先拆：要几个接口？每个接口的业务规则是什么？查哪几张表？返回什么结构。这是写代码前的必备设计。

把团队已有的 Controller/Service 模板贴给 AI，要求“按此风格生成订单模块”，产出更贴合规范、Review 成本低。

Controller 只做参数校验+调用；Mapper/XML 只做 SQL，if 判断尽量在 Service 或 SQL 动态标签里完成，保持单一职责。

用枚举表达固定状态集合（如订单状态），避免魔法数字；状态流转写清楚前置条件；空值用 Optional 或提前 return 防御。
enum OrderStatus { CREATED, PAID, SHIPPED, DONE }

数据存储与持久化层 8 个知识点

SQL 基础：select、insert、update、delete、where、order by、limit。 详情 ›
四大操作 + 条件过滤 + 排序 + 分页。limit 在 MySQL 是 limit offset,size，分页要靠它，越深分页越慢（用游标/延迟关联优化）。
SELECT id,name FROM user
WHERE age > 18
ORDER BY id DESC
LIMIT 0,10;
易考形式考 SQL 各子句作用、limit 分页写法。
条件查询：等值、模糊查询、范围查询、in、is null。 详情 ›
等值用 =；模糊用 LIKE '%x%'（前导通配符会失效索引）；范围用 BETWEEN/>/<；IN 多值；NULL 用 IS NULL 不能用 =。
SELECT * FROM user WHERE name LIKE 'Tom%' AND age IN (18,19,20) AND deleted IS NULL;
易考形式考 LIKE 索引失效、IS NULL 写法、IN 用法。
多表关联基础：inner join、left join、主外键字段理解。 详情 ›
INNER JOIN 取交集；LEFT JOIN 保留左表全部、右表无匹配补 NULL。关联字段通常是外键，注意 ON 条件与 WHERE 条件的区别。
SELECT u.name, o.amount
FROM `user` u
LEFT JOIN `order` o ON u.id = o.user_id;
易考形式考 inner vs left 区别、ON vs WHERE、COUNT 含 NULL 问题。
表结构理解：字段类型、主键、索引、非空、默认值。 详情 ›
主键唯一标识一行；索引加速查询但拖慢写入；NOT NULL 约束必填；默认值避免 NULL。类型选错（如用 VARCHAR 存金额）会出精度/性能问题。
CREATE TABLE `user`(
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(50) NOT NULL,
  status TINYINT DEFAULT 0
);
易考形式考主键/索引/非空作用、类型选择。
MyBatis-Plus 基础 CRUD：save、getById、list、updateById、removeById。 详情 ›
继承 BaseMapper<T> 即获得通用 CRUD，无需写 XML。updateById 默认只更新非空字段（非 NULL 才拼 SQL）。
userMapper.insert(user);
User u = userMapper.selectById(1L);
userMapper.updateById(u);
userMapper.deleteById(1L);
易考形式考 BaseMapper 方法、updateById 的 NULL 忽略行为。
LambdaQueryWrapper/LambdaUpdateWrapper：eq、like、in、between、orderBy、select。 详情 ›
用方法引用写条件，编译期检查字段名、避免硬编码字符串。更新时用 LambdaUpdateWrapper 的 set 精确赋值（可显式置 NULL）。
lambdaQuery().eq(User::getName,"Tom").like(User::getEmail,"@a.com").list();
lambdaUpdate().eq(User::getId,1L).set(User::getStatus,null).update();
易考形式考 Lambda 写法、如何真正把字段更新为 NULL。
实体映射：@TableName、@TableId、@TableField、字段命名映射。 详情 ›
@TableName 指定表名；@TableId 主键（可选 AUTO 自增）；@TableField 映射字段，开启驼峰自动转下划线（userName→user_name）。
@TableName("t_user")
class User{
  @TableId(type=IdType.AUTO) Long id;
  @TableField("user_name") String userName;
}
易考形式考注解作用、驼峰转下划线、字段名不一致处理。
AI 辅助 SQL：能描述查询目标、表结构、条件，让 AI 生成并解释 SQL。 详情 ›
给 AI 表结构 DDL + 业务目标（“查近 7 天支付成功订单，按金额倒序前 10”），让它出 SQL 并解释执行计划。
易考形式考“如何向 AI 描述 SQL 需求”。

高并发与中间件层 7 个知识点

Redis 基础概念：缓存、Key-Value、过期时间、命中率、缓存穿透/击穿/雪崩的基本含义。 详情 ›
缓存放热点数据减少 DB 压力。命中率=命中/总请求。穿透=查不存在的 key（布隆过滤器/空值缓存）；击穿=热点 key 过期瞬间高并发打 DB（互斥锁/逻辑过期）；雪崩=大量 key 同时失效（错峰过期）。
命中率 = hits / (hits + misses)
易考形式考三者的定义与解决方案、命中率计算。
Redis 常见数据类型：String、Hash 的读写场景。 详情 ›
String 存单值（验证码、计数器、JSON）；Hash 存对象字段（用户信息），可单独改某字段，省内存。
SET code:13800138000 1234 EX 60   // 验证码60秒过期
HSET user:1 name Tom age 18  // 哈希存用户
易考形式考 String vs Hash 选型、典型场景。
RedisTemplate/StringRedisTemplate 基础使用：set、get、delete、expire、opsForHash。 详情 ›
StringRedisTemplate 专管字符串（推荐，避免序列化乱象）；opsForValue() 做 KV，opsForHash() 做哈希。expire 设过期。
stringRedisTemplate.opsForValue().set("k","v", Duration.ofMinutes(5));
String v = stringRedisTemplate.opsForValue().get("k");
stringRedisTemplate.delete("k");
易考形式考 API 用法、StringRedisTemplate 与 RedisTemplate 区别。
缓存使用流程：先查缓存、未命中查数据库、写入缓存、设置过期时间。 详情 ›
标准 Cache-Aside：读时先查缓存，没有再查 DB 并回填缓存并设过期；写时先更新 DB 再删除缓存（或更新缓存），保证最终一致。
// 读
String v = redis.get(key);
if (v == null) {
  v = db.load(key);
  redis.set(key, v, 5, MINUTES); // 回填+过期
}
易考形式考 Cache-Aside 标准读流程、写时删缓存还是更新缓存。
MQ 基础概念：生产者、消费者、Topic/Queue、消息发送、消费确认。 详情 ›
生产者发消息，MQ 解耦/削峰/异步；Queue 点对点（一个消费者）、Topic 发布订阅（多消费者）。消费确认保证不丢（ack）。RabbitMQ 用 basicAck，失败用 basicReject/Nack 进死信。
// RabbitMQ 手动ack
@RabbitListener(queues="q")
public void on(Message m, Channel c) throws IOException {
  try { handle(m); c.basicAck(m.getMessageProperties().getDeliveryTag(), false); }
  catch(Exception e){ c.basicNack(tag,false,false); } // 进死信
}
易考形式考 Topic vs Queue、ack/死信机制、basicReject vs Nack。
基础消息代码套用：根据现有模板生成发送消息和消费消息代码。 详情 ›
按团队模板填 exchange/routingKey/queue，发送用 convertAndSend，消费用 @RabbitListener 或 @KafkaListener 注解。
rabbitTemplate.convertAndSend("ex","routing.key", payload);
kafkaTemplate.send("topic", key, payload);
易考形式考发送/消费注解与模板参数。
AI 辅助中间件学习：能让 AI 结合业务场景解释为什么使用缓存或 MQ。 详情 ›
把“秒杀下单慢、DB 被打挂”贴给 AI，让它给出“引入 Redis 缓存热点库存 + MQ 异步扣减”的方案与理由。
易考形式考“为何用缓存/MQ”的场景论证。

微服务架构层 5 个知识点

微服务基础概念：服务拆分、服务注册发现、服务调用、配置中心、网关。 详情 ›
把单体拆成独立部署的小服务；Nacos/Eureka 做注册发现；OpenFeign 做服务调用；Nacos 做配置中心；Gateway 做统一入口与鉴权。

本地启动流程：按运行手册启动依赖服务、应用服务、检查端口和配置。 详情 ›
先起中间件（MySQL/Redis/MQ/Nacos），再起应用；盯启动日志看端口、数据源、注册是否成功。
易考形式考启动顺序、依赖服务检查。
联调问题定位：读取启动日志、接口日志、依赖连接错误、端口占用、配置缺失。 详情 ›
Connection refused=依赖没起/地址错；Address already in use=端口被占；No qualifying bean=配置/扫描缺失。先看日志堆栈第一行。
易考形式考常见启动报错含义与定位思路。
常见依赖问题：版本冲突、配置文件环境错误、服务地址错误、注册失败。 详情 ›
