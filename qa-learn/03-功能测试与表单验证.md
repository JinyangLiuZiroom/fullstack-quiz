## 2. 核心概念：功能测试怎么设计

功能测试 = 对照**需求文档/验收标准**，验证「该有的功能都有、不对的被拦住」。

**两大用例设计方法**：
- **等价类划分**：把输入分成「有效等价类」（应该通过的）和「无效等价类」（应该被拒的），每类取代表值。例如年龄 18-120：有效取 30，无效取 10、150。
- **边界值分析**：重点测边界 ±1。年龄 18-120：测 17、18、120、121。

### 表单验证的测试维度

| 维度 | 要测什么 |
|---|---|
| 必填 | 空着提交，是否拦截 + 提示 |
| 格式 | 邮箱/手机/身份证格式错，是否拦截 |
| 长度 | 最短/最长边界，超长截断还是报错 |
| 类型 | 数字框输字母、日期框输文本 |
| 范围 | 数值越界（负数、超过 max） |
| 重复提交 | 快速点两次、网络慢时重复点 |
| 防抖/节流 | 连续点击只发一次请求 |
| 错误提示 | 提示文案准确、位置明显、不遮挡 |
| 前后端一致 | 前端拦了，后端也拦（不靠前端裸奔） |

> **关键原则**：前端验证是体验，**后端验证才是安全底线**。功能测试要确认后端也做了校验（绕过前端直接打接口仍能拦截），否则前端被绕过就有安全问题。

## 3. 快速开始：注册表单验证清单

需求：用户名（必填，3-20 字）、邮箱（必填，格式）、密码（必填，8-20 位含字母数字）。

用例：
```
1. 全填正确 → 成功
2. 用户名空 → 提示「用户名必填」，不提交
3. 用户名 2 字 → 提示长度不足
4. 用户名 21 字 → 提示超长
5. 邮箱格式错（a@） → 提示邮箱格式
6. 密码 7 位 → 提示至少 8 位
7. 密码纯数字 → 提示需含字母
8. 快速双击提交 → 只创建一条（防重复）
9. 绕过前端直接 POST 空用户名 → 后端返回 400（安全底线）
```

## 4. 进阶用法

### 4.1 重复提交与防抖验证

```js
// 前端防重复：提交中禁用按钮
const [submitting, setSubmitting] = useState(false);
async function submit() {
  if (submitting) return;          // 防重入
  setSubmitting(true);
  try { await api.create(form); } finally { setSubmitting(false); }
}
// 按钮 disabled={submitting}
```

功能测试：连续点 5 次提交按钮，观察网络面板只发 1 个请求；后端也要有幂等（如唯一索引/令牌）兜底。

### 4.2 错误提示的可测性

- 提示文案要明确（「邮箱格式不正确」而非「输入有误」）。
- 位置在对应字段下方，方便自动化定位。
- 多错误时是否都展示（还是只第一个）。

### 4.3 异常输入

- 特殊字符：`' " < > &`（防 XSS，模块十六会讲）
- 超长字符串（压测输入框/数据库）
- 全空格、emoji、中文标点

## 5. 常见坑与排错表

| 现象 | 根因 | 解决 |
|---|---|---|
| 只测了「填对能过」 | 等价类/边界没用 | 补无效等价类 + 边界值用例 |
| 前端拦了但后端没拦 | 只靠前端验证 | 确认后端也校验（模块二 打接口验证） |
| 快速双点创建两条 | 没防重复提交 | 前端禁用 + 后端幂等（唯一索引/令牌） |
| 错误提示看不懂 | 文案太泛 | 明确、定位到字段 |
| 长度边界没测 | 只测了典型值 | 测 min-1/min/max/max+1 |
| 网络慢时重复提交 | 没禁用按钮/没节流 | 提交中 disabled + 防抖 |
| 特殊字符导致崩溃 | 没做转义/校验 | 输入做白名单/转义（XSS 防护） |
| 多字段错误只报一个 | 只校验了第一个 | 确认能汇总所有错误 |

## 6. 完整实战：把注册表单测成「铁桶」

按第 3 节 9 条用例逐条执行（含第 9 条绕过前端打接口验证后端拦截）。再用边界值补：用户名 3/20 字、密码 8/20 位各边界。

**验收**：9+ 条用例全有预期结果；前端后端双重拦截；重复提交只落一条；所有错误提示明确且定位准确。

---

## 7. 最佳实践

- 用等价类 + 边界值设计用例，别只测 happy path。
- 必测「前后端双重校验」：后端是安全底线，不能只靠前端。
- 表单必测重复提交（防抖 + 后端幂等）。
- 错误提示要具体、定位到字段，便于人和自动化识别。
- 特殊字符/超长/越界都要有负面用例。
- 多错误场景确认能汇总展示，不是只报第一个。
