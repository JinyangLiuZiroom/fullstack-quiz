# 模块六：质量工程与质量门禁（完整学习指南）

> **学习目标**：从「测试是最后一步」升级到「质量工程是全流程」，理解质量度量（怎么量化质量）、质量门禁（卡点不放烂代码）、缺陷跟踪（闭环管理），能参与团队质量体系建设。
> **适合谁**：觉得质量就是「测试同学找 bug」、不知道覆盖率/门禁/缺陷生命周期的同学。
> **学完能做什么**：定义一套质量指标、在 CI 设质量门禁（覆盖率/单测通过/代码扫描）、用缺陷生命周期跟踪 bug 闭环。

## 2. 核心概念

### 2.1 质量工程（QE）视角

质量不是测出来的，是**设计 + 开发 + 测试 + 运维**全流程保障的。QE 做的是：
- 左移：需求可测性、开发自测。
- 自动化：金字塔各层自动化。
- 度量：用数据看质量趋势。
- 门禁：在流水线上卡住不达标的交付。

### 2.2 质量度量（常见指标）

| 指标 | 含义 | 怎么用 |
|---|---|---|
| 缺陷密度 | 每千行代码 bug 数 | 横向对比模块健康度 |
| 覆盖率 | 单测覆盖代码比例 | 门禁下限（如 ≥ 60%） |
| 缺陷遗留率 | 上线后发现的 bug / 总 bug | 反映测试有效性 |
| 平均修复时长（MTTR） | 从发现到修复平均耗时 | 反映响应速度 |
| 自动化率 | 自动化用例占比 | 反映回归效率 |
| 构建成功率 | CI 绿的比例 | 反映代码健康 |

> 度量是为了**改进**，不是 KPI 打压。避免「为了覆盖率写无意义单测」的畸变。

### 2.3 质量门禁（Quality Gate）

在 CI 流水线设卡点，不达标**不允许合并/发布**：

```
代码提交 → 编译 → 单测+覆盖率 → 代码扫描(Sonar) → 门禁判断
                                      ↓ 不达标
                                   阻断合并 + 通知
```

常见门禁：单测通过率 100%、覆盖率 ≥ 阈值、无严重代码扫描问题、无高危依赖漏洞。

### 2.4 缺陷生命周期

```
新建(New) → 指派(Assigned) → 处理中(In Progress) → 已修复(Fixed)
→ 验证(Verifying) → 关闭(Closed) / 打回(Reopened)
```

每个 bug 要有：标题、复现步骤、严重级别（致命/严重/一般/建议）、环境、截图/日志、负责人。

## 3. 快速开始：给项目设质量门禁

在 CI 配置（模块九）里：

```yaml
# 伪代码：门禁判断
build:
  - mvn test                  # 单测必须全过
  - coverage >= 60%           # 覆盖率门禁
  - sonar-scanner             # 静态扫描
  - if fail: block_merge      # 不达标阻断
```

缺陷跟踪用看板（Jira/禅道/Tapd）：每个 bug 走完整生命周期，禁止「口头说修了我信了」——必须验证后关闭。

---

## 4. 进阶用法

### 4.1 分层门禁

- **提交门禁**（快）：编译 + 单测 + 基础 lint，秒级反馈。
- **合并门禁**（中）：覆盖率 + 代码扫描 + 接口冒烟。
- **发布门禁**（重）：完整回归 + 性能 + 安全扫描。

越往前越轻量、越快，让问题尽早暴露。

### 4.2 缺陷根因分析

反复出现的同类缺陷，做根因分析（5 Why）：是需求不清？公共组件有坑？用例缺失？从流程上根治，而非每次手工补。

### 4.3 质量趋势看板

把覆盖率、缺陷密度按版本画趋势线，团队能看到「质量在变好还是变差」，而不是只看单点。

---

## 5. 常见坑与排错表

| 现象 | 根因 | 解决 |
|---|---|---|
| 为了覆盖率写凑数单测 | 门禁只看数字 | 门禁结合断言质量 + mutation 测试；考核改进非数字 |
| 门禁太严没人能过 | 阈值不合理 | 循序渐进提阈值，先 40% 再 60% |
| bug 口头说修了自己信了 | 没走验证闭环 | 必须 Verifying→Closed，测试验证才算 |
| 缺陷无严重级别 | 优先级混乱 | 统一致命/严重/一般/建议分级 |
| 只测不度量 | 不知质量趋势 | 建度量看板，看趋势 |
| 门禁只在发布前卡 | 反馈太晚 | 提交/合并阶段就设轻门禁 |
| 缺陷反复出现 | 没根因分析 | 5 Why 根治 + 转回归用例 |
| 质量=测试的事 | 职责错位 | 质量是全员责任，开发自测+QE 保障 |

---

## 6. 完整实战：搭一套最小质量门禁

给团队现有项目：
1. 选指标：单测通过率、覆盖率阈值、严重缺陷数。
2. CI 加门禁：单测不过/覆盖率不达标阻断合并。
3. 缺陷流程固化：New→...→Closed，验证才关。
4. 周报看板：覆盖率趋势 + 本周缺陷遗留。

**验收**：有人提交烂代码会被门禁自动拦下；bug 必须验证才能关；团队能看到质量趋势。

---

## 7. 最佳实践

- 质量是全流程全员责任，不是测试收尾。
- 度量用于改进，门禁阈值循序渐进（别一上来 90%）。
- 多层门禁：提交轻、合并中、发布重，问题尽早暴露。
- 缺陷必须走完整生命周期，验证后才关闭，杜绝「口头修复」。
- 反复缺陷做根因分析（5 Why），转回归用例防复发。
- 建质量趋势看板，看变化而非单点。
