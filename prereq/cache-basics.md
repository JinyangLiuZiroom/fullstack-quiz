# 缓存概念（前置知识补完）

> 一句话：把热点数据放更快的存储（内存），减少查 DB，扛住高并发。

## 你应该会什么（检验）
- 知道缓存 = 把热点数据放更快的存储（内存），减少查 DB
- 基本数据结构：String / Hash / List / Set / ZSet（Redis）

## 30 秒上手
```
请求 → 先查缓存（内存，毫秒级）
 命中 → 直接返回
 未命中 → 查 DB，写入缓存，再返回
```
典型：用户信息、商品详情、排行榜放缓存。

## 一个练习
画一遍「查缓存 → 命中/未命中 → 回源 DB」的流程。做完回主文章（模块九专门讲 Redis 实战）。

## 常见误解
- 缓存和 DB 可能不一致（改了 DB 没更缓存）→ 有「缓存一致性」问题要解决。
- 缓存不是备份，丢数据要从 DB 重新加载，不能依赖它兜底。
