# 模块十六：前端性能优化（完整学习指南）

> **学习目标**：理解「页面为什么慢」以及从哪里下手，掌握加载阶段（打包/分包/预加载）、渲染阶段（重排重绘/防抖节流/虚拟列表）、资源阶段（缓存/压缩）的主流优化手段，能看懂 Core Web Vitals 三个指标（LCP/INP/CLS），并避开「首屏白屏、列表卡死、输入抖动、图片拖慢」等典型坑。
> **适合谁**：能写完整页面、会用 Vue/路由/请求，但页面在低端机或大数据量下明显卡顿，不知从哪优化的同学。
> **学完能做什么**：给一个首屏白屏的项目做代码分割 + 路由懒加载，给一个万条列表做虚拟滚动，给搜索框做防抖，跑出可量化的性能提升。

## 2. 核心概念一：Core Web Vitals 三大指标

Google 用来衡量体验的三个关键指标（也是面试常客）：

| 指标 | 含义 | 好的阈值 | 常见拖慢原因 |
|---|---|---|---|
| **LCP** | 最大内容绘制（首屏主内容出现时间） | < 2.5s | 大图/阻塞 JS/慢接口 |
| **INP** | 交互到下一次绘制（点击响应延迟） | < 200ms | 长任务占主线程 |
| **CLS** | 累积布局偏移（页面跳动） | < 0.1 | 图片无宽高、异步内容插入 |

> 记住这三个词，优化目标就是压低它们。DevTools → Lighthouse 一键测。

## 3. 核心概念二：加载优化（让资源更快到位）

### 3.1 路由懒加载（模块七讲过，性能第一招）

```js
const User = () => import('@/views/User.vue')   // 访问时才加载该页 JS
```

首屏只加载当前页，其余页面分包按需加载。

### 3.2 组件/库按需引入

- 组件库按需（模块十二的 unplugin）
- 大库按需：`import debounce from 'lodash/debounce'`，别 `import _ from 'lodash'`

### 3.3 代码分割与预加载

```js
// 预加载：空闲时提前拉可能要去的页
const User = () => import(/* webpackPrefetch: true */ '@/views/User.vue')
// 预连接：提前和 CDN 建连
<link rel="preconnect" href="https://cdn.x.com">
```

### 3.4 图片优化

```html
<img src="pic.webp" loading="lazy" width="300" height="200">
<!-- loading="lazy" 滚动到才加载；width/height 防 CLS 跳动 -->
```

- 用 WebP/AVIF 替代 PNG/JPG（体积小 30~70%）
- 小图标用 SVG 或雪碧图
- 大图用 CDN + 响应式 `srcset`

### 3.5 开启压缩与缓存（构建/服务器侧）

- 构建产物开 gzip/brotli（Vite 默认产出，服务器开启 `Content-Encoding: gzip`）
- 静态资源设长缓存（`Cache-Control: max-age=31536000, immutable`），文件名带 hash 防更新不生效

## 4. 核心概念三：渲染优化（让交互更顺）

### 4.1 减少重排重绘（模块十一提过）

```css
/* 动画用 transform/opacity，走合成层，不触发重排 */
.box { transition: transform 0.3s; }
.box.move { transform: translateX(100px); }
/* ❌ 别用 left/top 做动画，会重排 */
```

### 4.2 防抖与节流（高频事件必用）

```js
// 防抖：停止触发 N 毫秒后才执行（搜索输入）
function debounce(fn, wait = 300) {
  let t
  return (...args) => {
    clearTimeout(t)
    t = setTimeout(() => fn(...args), wait)
  }
}
input.oninput = debounce(() => fetchList(input.value), 300)

// 节流：每 N 毫秒最多执行一次（滚动/resize）
function throttle(fn, wait = 200) {
  let last = 0
  return (...args) => {
    const now = Date.now()
    if (now - last >= wait) { last = now; fn(...args) }
  }
}
window.onscroll = throttle(() => console.log('scroll'), 200)
```

> **防抖**用于「输入完再查」，**节流**用于「滚动/拖拽持续触发但限频」。

### 4.3 虚拟列表（万条数据不卡）

一次性渲染 1 万行 DOM 必卡。虚拟列表只渲染「视口内」的十几行：

```vue
<!-- 思路：容器固定高 + 内部偏移，只渲染可见项 -->
<template>
  <div class="viewport" @scroll="onScroll" style="height:400px;overflow:auto">
    <div :style="{ height: total * rowH + 'px' }">           <!-- 撑出滚动条 -->
      <div :style="{ transform: `translateY(${offset}px)` }"> <!-- 可见块偏移 -->
        <div v-for="item in visible" :key="item.id" :style="{ height: rowH + 'px' }">
          {{ item.text }}
        </div>
      </div>
    </div>
  </div>
</template>
```

生产用现成库：`vue-virtual-scroller`、`el-table` 的 `virtual-scroll` 等，别自己写边界。

### 4.4 长任务拆分（不阻塞主线程）

```js
// 大循环切成多段，让浏览器有空渲染
async function bigTask(list) {
  for (let i = 0; i < list.length; i++) {
    process(list[i])
    if (i % 100 === 0) await new Promise(r => setTimeout(r))  // 让出主线程
  }
}
```

## 5. 核心概念四：请求优化

- **合并请求**：列表+详情一次拿，少往返
- **并发控制**：`Promise.all` 但有上限，避免瞬间百个请求
- **缓存**：不常变的数据存 Pinia/localStorage，重复进页不重复拉
- **取消旧请求**：输入搜索时取消上一次未完成请求（模块三 Axios 取消令牌）

## 6. 常见坑与排错表

| # | 现象 | 根因 | 正确做法 |
|---|---|---|---|
| 1 | 首屏白屏久 | 单包巨大、没懒加载 | 路由懒加载 + 分包（3.1） |
| 2 | 引入整个 lodash 体积爆 | 默认全量 import | `import debounce from 'lodash/debounce'` |
| 3 | 图片加载时页面跳动 | 没设 width/height | 图片占位定宽高，防 CLS |
| 4 | 大图拖慢 LCP | PNG 未压缩 | 转 WebP/AVIF + CDN |
| 5 | 搜索输入狂发请求 | 每次按键都发 | 防抖 300ms（4.2） |
| 6 | 滚动卡顿 | 滚动里做重计算 | 节流 + 避免重排 |
| 7 | 万条列表浏览器卡死 | 全量渲染 DOM | 虚拟列表只渲染可见项（4.3） |
| 8 | 动画卡 | 用 left/top 触发重排 | 用 transform/opacity |
| 9 | 改了静态资源不更新 | 缓存没失效 | 文件名带 hash（Vite 默认） |
| 10 | 重复进页重复拉数据 | 没缓存 | Pinia/localStorage 缓存不常变数据 |
| 11 | 长循环卡 UI | 同步占用主线程 | 拆分 + setTimeout 让出（4.4） |
| 12 | 优化没效果 | 没先量就乱改 | 先 Performance/Lighthouse 定位瓶颈 |

## 7. 完整实战：优化一个卡顿列表页

**目标**：原页面一次性渲染 5000 条，滚动掉帧、输入搜索狂发请求。优化后：虚拟列表 + 防抖搜索 + 路由懒加载。

```vue
<script setup>
import { ref, computed } from 'vue'
import { debounce } from 'lodash/debounce'   // 按需

const all = ref(Array.from({ length: 5000 }, (_, i) => ({ id: i, text: '项' + i })))
const kw = ref('')
const rowH = 40

const filtered = computed(() =>
  all.value.filter(it => it.text.includes(kw.value))
)
const visible = ref([])
const offset = ref(0)

function onScroll(e) {
  const top = e.target.scrollTop
  const start = Math.floor(top / rowH)
  visible.value = filtered.value.slice(start, start + 15)
  offset.value = start * rowH
}
const onSearch = debounce((v) => { kw.value = v }, 300)
</script>

<template>
  <input @input="onSearch($event.target.value)" placeholder="搜索" />
  <div class="viewport" @scroll="onScroll" style="height:400px;overflow:auto">
    <div :style="{ height: filtered.length * rowH + 'px' }">
      <div :style="{ transform: `translateY(${offset}px)` }">
        <div v-for="it in visible" :key="it.id" :style="{ height: rowH + 'px' }">
          {{ it.text }}
        </div>
      </div>
    </div>
  </div>
</template>
```

**验收打勾**：
- [ ] 5000 条时 DOM 节点数 ≈ 15（而非 5000），滚动顺滑
- [ ] 输入搜索时网络请求被防抖（停止输入 300ms 才发）
- [ ] Lighthouse 跑分较优化前 LCP/INP 有改善
- [ ] 路由已懒加载，首屏 JS 体积下降

---

## 8. 最佳实践

1. **先量后优化**：Performance/Lighthouse 定位是网络还是 JS 卡。
2. **首屏优化靠分包**：路由懒加载 + 大库按需，首屏只装必要代码。
3. **图片用 WebP + lazy + 定宽高**，压 LCP 和 CLS。
4. **高频事件防抖/节流**，搜索防抖、滚动节流。
5. **大数据列表用虚拟滚动**，DOM 节点数恒定。
6. **动画走 transform/opacity**，避免重排。
7. **静态资源带 hash + 长缓存**，更新不冲突。
8. **不常变数据缓存**，减少重复请求。
