# 模块十四：前端工程化规范（ESLint / Prettier / husky）（完整学习指南）

> **学习目标**：理解为什么团队需要统一的代码规范与提交门禁，掌握 ESLint（代码检查）、Prettier（格式化）、husky + lint-staged（提交前拦截）、commitlint（提交信息规范）、EditorConfig（跨编辑器一致）的配置与协作，能独立给一个 Vite 项目装上这套「质量护栏」，并避开「ESLint 和 Prettier 打架、husky 不生效、commit 被拒不知原因」等典型坑。
> **适合谁**：能跑 Vite 项目、会 `npm install`，但项目里还没接任何规范，或接了总报冲突、提交老被拦的同学。
> **学完能做什么**：给项目装上 ESLint+Prettier，配置 husky 在 `git commit` 时只检查改动文件，提交信息不符合规范直接拦截，团队风格自动统一。

---

## 1. 前置知识（先确认你会这些）

- 模块五：会用 Vite、`npm run dev/build`
- 知道 `package.json` 的 `scripts` 怎么加命令
- 用过 Git 基本提交（`git add` / `git commit`）
- 知道「lint」= 静态检查代码问题（不运行，只扫描）

> 规范不是束缚，是**团队协作的护栏**：统一风格减少 Review 争吵；提交前拦截低级错误（未使用变量、类型错）；提交信息规范让 `git log` 可读、能自动生成 changelog。

---

## 2. 核心概念：四件套各管什么

| 工具 | 职责 | 类比 |
|---|---|---|
| **ESLint** | 找代码问题（未定义变量、危险写法、风格） | 严格的代码审查员 |
| **Prettier** | 统一格式（缩进、引号、换行） | 格式化打印机 |
| **husky** | 在 git 钩子（commit/pre-push）触发脚本 | 提交口的安检门 |
| **lint-staged** | 只对「暂存区（本次改动）文件」跑检查 | 只检要上车的行李 |

> **ESLint vs Prettier 关系**：ESLint 也能管格式，但和 Prettier 重叠会打架。标准做法：**ESLint 管「代码质量」（规则带 `error`/`warn`），Prettier 管「格式」**，用 `eslint-config-prettier` 关掉 ESLint 的格式规则，避免冲突。

## 3. 快速开始：最小可用配置

### 3.1 安装

```bash
npm install -D eslint prettier
npm install -D eslint-config-prettier eslint-plugin-vue
npm install -D @vue/eslint-config-typescript   # 用 TS 时
```

### 3.2 ESLint 配置 `.eslintrc.cjs`

```js
module.exports = {
  root: true,
  env: { browser: true, es2022: true },
  extends: [
    'eslint:recommended',
    'plugin:vue/vue3-recommended',
    '@vue/eslint-config-typescript',
    'prettier',                 // 关键：关闭所有和 Prettier 冲突的格式规则
  ],
  rules: {
    'no-unused-vars': 'warn',
    'vue/multi-word-component-names': 'off',
  },
}
```

### 3.3 Prettier 配置 `.prettierrc`

```json
{
  "semi": false,
  "singleQuote": true,
  "printWidth": 80,
  "trailingComma": "none"
}
```

> 团队统一这文件，所有人格式一致。编辑器装 Prettier 插件并设「保存时格式化」。

### 3.4 跑检查

```json
// package.json scripts
{
  "lint": "eslint . --ext .vue,.js,.ts",
  "format": "prettier --write \"src/**/*.{vue,js,ts,css}\""
}
```

```bash
npm run lint       # 查错
npm run format     # 自动格式化
```

## 4. 进阶用法：提交门禁

### 4.1 husky 装钩子

```bash
npm install -D husky
npx husky init     # 生成 .husky/ 目录和 prepare 脚本
```

`npx husky init` 会在 `package.json` 加 `"prepare": "husky"`（装依赖后自动启用 husky）。

### 4.2 lint-staged：只查改动文件

```bash
npm install -D lint-staged
```

```json
// package.json
{
  "lint-staged": {
    "*.{vue,js,ts}": ["eslint --fix", "prettier --write"],
    "*.{css,md}": ["prettier --write"]
  }
}
```

### 4.3 pre-commit 钩子

```bash
# 创建 .husky/pre-commit
npx husky add .husky/pre-commit "npx lint-staged"
```

效果：`git commit` 时，husky 触发 `lint-staged`，**只对本次 add 的文件**跑 eslint 自动修复 + prettier 格式化。有 error 且修不了 → 提交中断。

### 4.4 commitlint：提交信息规范

```bash
npm install -D @commitlint/cli @commitlint/config-conventional
```

```js
// commitlint.config.cjs
module.exports = { extends: ['@commitlint/config-conventional'] }
```

```bash
npx husky add .husky/commit-msg "npx --no -- commitlint --edit $1"
```

规范提交格式：`type(scope): subject`
```
feat(user): 新增用户列表页
fix(login): 修复 token 过期未跳转
docs: 补充 README
```
`type` ∈ feat/fix/docs/style/refactor/test/chore。不符合 → commit 被拒。

## 5. EditorConfig（跨编辑器一致）

```ini
# .editorconfig
root = true
[*]
charset = utf-8
indent_style = space
indent_size = 2
end_of_line = lf
insert_final_newline = true
trim_trailing_whitespace = true
```

> 不同人用 VSCode/WebStorm，EditorConfig 让缩进/换行/编码自动一致，避免「你 2 空格我 4 空格」的无意义 diff。

## 6. 常见坑与排错表

| # | 现象 | 根因 | 正确做法 |
|---|---|---|---|
| 1 | ESLint 和 Prettier 抢同一格式，互相改 | 两者都管格式规则 | ESLint extends 里加 `'prettier'` 关掉格式规则 |
| 2 | `npm run lint` 卡很久/全量扫 | 没限定文件范围 | 用 `--ext` 限定，或 lint-staged 只查改动 |
| 3 | husky 不触发 | 没 `npx husky init`（无 prepare） | 确保 package.json 有 `"prepare":"husky"` 且依赖已装 |
| 4 | pre-commit 报错但看不懂 | ESLint error 未修复 | 看报错文件行号；`eslint --fix` 能修的会自动修 |
| 5 | commit 被拒提示 commitlint | 提交信息不合规范 | 按 `type(scope): subject` 写 |
| 6 | 每次 commit 都全量 lint 慢 | 没用 lint-staged | 用 lint-staged 只查暂存区文件 |
| 7 | `husky add` 命令不存在（husky v9） | v9 改了 API | v9 直接写 `.husky/pre-commit` 文件内容 |
| 8 | Windows 上钩子不执行 | 钩子无执行权限/行尾 CRLF | 钩子文件用 LF；husky 已处理权限 |
| 9 | CI 没拦住格式问题 | 只本地 husky，没 CI 门禁 | CI 里也跑 `npm run lint`（模块五提过 tsc 门禁同理） |
| 10 | 别人拉下来 husky 没生效 | 没装依赖/prepare 未跑 | 重新 `npm install` 触发 prepare |
| 11 | eslint 报 vue 文件不识别 | 没装 eslint-plugin-vue | extends 加 `plugin:vue/vue3-recommended` |
| 12 | TS 项目 ESLint 报错多 | 没接 @vue/eslint-config-typescript | extends 加该配置 |

## 7. 完整实战：给 Vite 项目装护栏

**步骤 1**：装依赖
```bash
npm i -D eslint prettier eslint-config-prettier eslint-plugin-vue @vue/eslint-config-typescript husky lint-staged @commitlint/cli @commitlint/config-conventional
```

**步骤 2**：放配置文件（`.eslintrc.cjs` / `.prettierrc` / `commitlint.config.cjs` / `.editorconfig`，内容见上）

**步骤 3**：初始化 husky 与钩子
```bash
npx husky init
npx husky add .husky/pre-commit "npx lint-staged"
npx husky add .husky/commit-msg "npx --no -- commitlint --edit $1"
```

**步骤 4**：`package.json` 加脚本与 lint-staged 配置（见上）

**验收打勾**：
- [ ] 故意写个 `const a = 1` 不用的变量，`npm run lint` 报 `no-unused-vars`
- [ ] `git commit` 时自动格式化本次改动文件
- [ ] 提交信息写成 `改了下` 被 commitlint 拒绝；写成 `fix: 修复xxx` 通过
- [ ] 同事 `git clone` 后 `npm install` 自动启用 husky（prepare 触发）

## 8. 最佳实践

1. **ESLint 管质量、Prettier 管格式**，用 `eslint-config-prettier` 关冲突。
2. **husky + lint-staged 放 pre-commit**，只查本次改动，不拖累提交速度。
3. **commitlint 用 conventional 规范**，提交信息可生成 changelog。
4. **EditorConfig 必加**，跨编辑器统一缩进/换行。
5. **CI 也跑 lint/tsc**，不靠本地钩子兜底（有人 `--no-verify` 跳过）。
6. **规则分级**：`error` 拦截致命问题，`warn` 只提示不影响提交（团队磨合期可先 warn）。
7. **保存即格式化**：编辑器配 Prettier on save，减少提交时冲突。
