# 模块十三：移动端适配（完整学习指南）

> **学习目标**：掌握 H5 在手机上的适配方案，理解 viewport、rem/vw 两种主流适配思路、媒体查询、1px 物理像素边框、安全区（刘海/底部小黑条），能独立写出「在任何主流机型上不变形、不溢出、不串位」的移动端页面，并避开「字体随屏幕忽大忽小、1px 变粗、底部被小黑条挡住」等典型坑。
> **适合谁**：会写 HTML/CSS，做过 PC 页面，但第一次做「要在手机浏览器里打开」的 H5，发现样式全乱的同学。
> **学完能做什么**：用 vw 方案搭一个自适应手机宽的列表页，处理 1px 边框和安全区，在 375/414/750 设计稿下都正常。

## 2. 核心概念一：像素与 DPR

- **CSS 像素**：你写 `width: 100px` 的「px」，是逻辑单位
- **物理像素**：屏幕实际发光的点，如 iPhone 是 1170×2532 物理点
- **DPR（设备像素比）** = 物理像素 / CSS 像素。DPR=2 时，1 个 CSS 像素 = 2×2 个物理像素

```js
window.devicePixelRatio   // 常见 2 或 3（Retina 屏）
```

**结论**：你写的 px 会被设备按 DPR 放大到物理像素。所以「同样 100px」在高 DPR 屏上占的物理尺寸更小——这就是为什么 PC 的 px 直接搬手机会显得小。

---

## 3. 核心概念二：viewport（必须的第一行）

手机浏览器默认会用一个「虚拟宽度（约 980px）」渲染页面再缩放，导致你写的 PC 布局被缩得很小。必须加：

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no">
```

- `width=device-width`：视口宽度 = 设备 CSS 宽度（如 iPhone 375px），不缩放
- `initial-scale=1`：初始不缩放
- `user-scalable=no`：禁双击缩放（H5 应用常用，但无障碍场景慎用）

> **没这行 meta，移动端页面必崩**。这是移动 H5 的第一行代码。

---

## 4. 核心概念三：rem 适配方案

`rem` 相对于**根元素 `<html>` 的 font-size**。思路：JS 动态设 `html` 的 `font-size` 随屏宽变化，页面所有尺寸用 `rem`，就整体跟着缩放。

### 4.1 手设根字号（flexible 思路）

```js
// 以设计稿宽 375 为基准，设 html font-size = 屏宽 / 10
function setRem() {
  const w = document.documentElement.clientWidth
  document.documentElement.style.fontSize = w / 10 + 'px'   // 375 屏 → 37.5px
}
setRem()
window.addEventListener('resize', setRem)
```

然后 CSS 里：`1rem = 37.5px`（375 屏）。设计稿 75px 的元素 = `75/37.5 = 2rem`。屏宽变 414 时根字号变 41.4px，2rem 自动变 82.8px，等比放大。

### 4.2 用 postcss-pxtorem 自动换算（工程化推荐）

写 CSS 仍用 px（按设计稿），构建时插件自动转 rem：

```bash
npm install -D postcss-pxtorem autoprefixer
```

```js
// postcss.config.js
module.exports = {
  plugins: {
    'postcss-pxtorem': {
      rootValue: 37.5,        // 设计稿 375 时 1rem=37.5px
      propList: ['*'],
    },
  },
}
```

> 配合上面的 `setRem`（rootValue=37.5 对应 375 稿）。换设计稿宽度改 rootValue 即可。

## 5. 核心概念四：vw 适配方案（更现代，免 JS）

`vw` = 视口宽度的 1%。`100vw` = 屏宽。把设计稿 px 直接换算成 vw：

```
375 稿上的 75px = 75 / 375 * 100vw = 20vw
```

用 `postcss-px-to-viewport` 自动转：

```bash
npm install -D postcss-px-to-viewport-8-plugin
```

```js
// postcss.config.js
module.exports = {
  plugins: {
    'postcss-px-to-viewport-8-plugin': {
      viewportWidth: 375,      // 设计稿宽度
      unitToConvert: 'px',
      viewportUnit: 'vw',
    },
  },
}
```

**rem vs vw 怎么选**：
- **vw 方案**：纯 CSS、无需 JS 监听 resize，简单。**缺点**：不支持「最大宽度限制」（PC 上打开会超大）。
- **rem 方案**：可加「屏宽上限」逻辑（如 `max-width: 540px` 不再放大），PC 预览友好。
- 现代项目多用 **vw**（简单），或 **rem + 最大宽度**（兼顾 PC 预览）。

## 6. 核心概念五：媒体查询（断点适配）

针对区间做差异化样式：

```css
/* 手机 */
.container { padding: 12px; }
/* 平板及以上 */
@media (min-width: 768px) {
  .container { padding: 24px; max-width: 720px; margin: 0 auto; }
}
```

常见断点：手机 `<768`、平板 `768–1024`、桌面 `>1024`。

---

## 7. 核心概念六：1px 边框与物理像素

高 DPR 屏上，`border: 1px` 实际渲染成 2~3 物理像素，显得「粗」。要真 1 物理像素边框：

```css
/* 用 transform 缩放实现 1px 物理边框 */
.hairline {
  position: relative;
}
.hairline::after {
  content: '';
  position: absolute;
  left: 0; right: 0; bottom: 0;
  border-bottom: 1px solid #ddd;
  transform: scaleY(0.5);   /* DPR=2 时缩到 0.5 → 1 物理像素 */
  transform-origin: 0 0;
}
```

或更简：直接用 `0.5px`（部分浏览器支持）或上面伪元素法。

## 8. 核心概念七：安全区（刘海/底部小黑条）

iPhone 有圆角、刘海、底部 Home 指示条，内容可能被挡。用 `env()` 留安全边距：

```css
.safe-bottom {
  padding-bottom: calc(12px + env(safe-area-inset-bottom));
  /* env(safe-area-inset-bottom) 在有小黑条的机型上是那条高度，普通机型是 0 */
}
```

> 配合 `<meta name="viewport" content="... viewport-fit=cover">` 才能让 `env()` 生效（`viewport-fit=cover` 让页面铺满安全区外）。

## 9. 常见坑与排错表

| # | 现象 | 根因 | 正确做法 |
|---|---|---|---|
| 1 | 手机打开页面被缩得很小 | 没加 viewport meta | 加 `width=device-width` |
| 2 | rem 方案下尺寸不对 | rootValue 与设计稿不匹配 | rootValue 设成「设计稿宽/10」 |
| 3 | 字体也跟着 rem 放大变小 | 字体用了 rem | 字体用 px 固定（或 clamp 限制范围） |
| 4 | PC 浏览器打开 H5 巨大 | vw 方案无上限 | 加 `max-width` 容器或改用 rem+上限 |
| 5 | 1px 边框在 Retina 上很粗 | 1 CSS px = 多物理像素 | 用 transform scaleY(0.5) 伪元素法 |
| 6 | 底部按钮被小黑条挡 | 没留安全区 | `padding-bottom: env(safe-area-inset-bottom)` |
| 7 | env() 不生效 | viewport 没 `viewport-fit=cover` | meta 加 `viewport-fit=cover` |
| 8 | 图片变形 | 只设宽或高压 | 用 `object-fit: cover` 或固定宽高比容器 |
| 9 | 点击有 300ms 延迟 | 老浏览器双击缩放 | 现代浏览器加 viewport 后已无；必要时用 touch 事件 |
| 10 | 单位换算插件没生效 | 配置文件名/格式错（postcss.config.cjs） | 确认是 `.cjs` 或 package.json 配 postcss |
| 11 | 设计稿 750 但按 375 算 | 两倍图没除 2 | 750 稿 rootValue 设 75（或 px-to-viewport viewportWidth:750） |
| 12 | 横竖屏切换布局错 | 没监听 orientation/resize | rem 方案监听 resize；或用 vw 自适应 |

## 10. 完整实战：vw 自适应列表页

**目标**：设计稿 375，列表项间距/字号用 px 写，构建自动转 vw，在 375/414 都比例正确；底部 tab 栏留安全区。

```html
<!-- index.html -->
<meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover">
```

```js
// postcss.config.cjs
module.exports = {
  plugins: {
    'postcss-px-to-viewport-8-plugin': {
      viewportWidth: 375,
      unitToConvert: 'px',
      viewportUnit: 'vw',
    },
  },
}
```

```vue
<template>
  <div class="page">
    <ul class="list">
      <li class="item" v-for="i in 5" :key="i">
        <img class="avatar" src="https://picsum.photos/80" />
        <div class="info">
          <p class="name">用户 {{ i }}</p>
          <p class="desc">这是一段描述文字</p>
        </div>
      </li>
    </ul>
    <nav class="tabbar">首页 · 我的</nav>
  </div>
</template>

<style scoped>
.page { padding: 16px; }
.item { display: flex; gap: 12px; padding: 12px 0; border-bottom: 1px solid #eee; }
.avatar { width: 48px; height: 48px; border-radius: 8px; object-fit: cover; }
.name { font-size: 16px; margin: 0; }
.desc { font-size: 13px; color: #888; margin: 4px 0 0; }
.tabbar {
  position: fixed; left: 0; right: 0; bottom: 0;
  height: 50px; line-height: 50px; text-align: center;
  background: #fff; border-top: 1px solid #eee;
  padding-bottom: env(safe-area-inset-bottom);   /* 安全区 */
}
</style>
```

**验收打勾**：
- [ ] 375 屏和 414 屏下，列表项相对比例一致（不溢出、不缩小过头）
- [ ] 底部 tab 栏在 iPhone 不被小黑条遮挡
- [ ] 头像不变形（圆角裁剪正常）
- [ ] 浏览器 DevTools 切不同机型尺寸，布局不崩

## 11. 最佳实践

1. **第一行必加 viewport meta**，`viewport-fit=cover` 配合安全区。
2. **适配方案选 vw（简单）或 rem+上限（兼顾 PC）**，别手写媒体查询算每个尺寸。
3. **用 postcss 插件自动转单位**，写 CSS 仍用设计稿 px。
4. **设计稿 750 要除 2**（rootValue/viewportWidth 设 75 或 750），别直接当 375 算。
5. **字体用 px 固定或 clamp**，别用 rem 否则随屏乱变。
6. **1px 边框用 transform scale 伪元素**实现物理 1px。
7. **底部固定元素加 `env(safe-area-inset-bottom)`**，防小黑条遮挡。
8. **图片用 `object-fit: cover`**，防变形。
